# Run note: power of whole tasks, every HLS point at every size, nangate45 and nangate15, 29 Oct 2026

The energy of whole tasks: every hardware point of tiers done and untiered (119, of which 3 are parked for a RAM macro) at every size in its hls-exercises `rtl/<point>/sizes.txt`, on both technologies, with `pwr run ... --size all`. rand64, seed 0; cycles compared exactly with `cosim_lat_avg`; PrimePower on the mapped netlists in `syn/runs/` (nothing there written). The HLS baseline for snax-forge's blocks; `results/hls/report_energy.md` has the tables. Dynamic energy only (X13). Repos: snax-forge-experiments from `b648528`, hls-exercises `fce57e2`.

**The 64-beat runs were not in the repo.** The prompt takes them as done ("prompt 2 measured every HLS point ... at 64 beats, on both technologies"), but `power_pt.csv` held only vecadd on nangate45 (`pwr_r1`), and nothing on nangate15. The estimate below needs them, so they ran first, here, with the same driver: every point at b64 (rowsum at m8_n64) on both technologies. They are committed with this run.

## Commands

```bash
git pull --ff-only                                    # both repos up to date and clean
# sim/runs/<tech>/ removed except _cells, both technologies; syn/runs/ untouched
export LMUTIL=/esat/micas-data/software/Mentor/questasim_2022.4/linux_x86_64/lmutil   # not on PATH here (L3)
pixi run pwr run 'done/*/*' 'untiered/*/*' --tech nangate45                 # 64 beats (prerequisite)
pixi run pwr run 'done/*/*' 'untiered/*/*' --tech nangate15
pixi run pwr run 'done/*/*' 'untiered/*/*' --tech nangate45 --size all      # every size in sizes.txt
pixi run pwr run 'done/*/*' 'untiered/*/*' --tech nangate15 --size all
pixi run python sim/report_energy.py                                        # results/hls/report_energy.md
```

## Changes to the driver

| change | why |
|---|---|
| `--size all`: every size in the point's `sizes.txt` (first token of each non-comment line; `(renamed ids)` ignored), one compile per point | the task sizes |
| netlist modules matched with leading space (`^\s*module`) | the first 64-beat batch on nangate45 failed 42 points: the multipliers of dot, vecmul and axpy were never dumped (PITFALLS DC6). Afterwards every module of all 232 netlists gets a dump scope (checked) |
| the sink counts beats only after reset | axpy opt drives `y_out_TVALID` in reset, and the clock's X -> 0 is a falling edge at time 0 (PITFALLS Q7) |
| the input-toggle check fails a run from 64 beats up, and records the count below | the first `--size all` pass failed 52 runs per technology on it, all at 2 to 8 beats, where no seed can pass (X19 amended) |
| `sim/report_energy.py` | writes `report_energy.md` from `power_pt.csv` |

Both 64-beat batches and both task batches were then run from the final code; vecadd's 64-beat rows equal `pwr_r1`'s to the digit.

The error follows the beats: the 64-beat run spreads a task's fixed cycles (pipeline fill and drain, the start and done states) over 64 beats, and a task of 2 beats pays them twice per beat. vsum `opt_w32` at n64 takes 5 cycles for 2 beats, 2.5 per beat against 1.047 at 64 beats, and the estimate is 38 to 40 % low. From 16 beats up the error is within -9.10 to +4.81 % (nangate45) and -8.70 to +2.70 % (nangate15), and its median from 128 beats up is +0.50 % and +0.25 %. A per-task term (HWCOST's E_0) is what the small sizes need.

## Odd things

- **The prerequisite 64-beat runs did not exist** (above); they were run here, and the first attempt found DC6 and Q7.
- **unopt's estimate is good on nangate15 and not on nangate45.** Median error over unopt's runs at another configuration: -1.37 % on nangate45, +0.00 % on nangate15; worst -22.84 % against -2.37 %. Per cycle, nangate45's clock group moves with the run length where nangate15's does not: vsum `unopt_w32` e_clk 9.58 pJ at 64 beats, 9.92 at n512 (16 beats), 13.03 at n64 (2 beats) on nangate45, against 4.62, 4.62, 4.60 on nangate15, at the same cycles per beat (67.0 to 67.5). Both libraries' flops have state-dependent clock-pin internal power (`when` on D and Q), so that alone does not explain it. Not traced.
- **The input-toggle check cannot pass at a few beats** (X19 amended): 52 runs per technology at 2 to 8 beats.
- **The same-configuration runs reproduce the 64-beat rows to the digit** across separate batches (48 per technology): the flow is deterministic.
- **The largest positive errors are the W = 1 opt and dace points at n512:** vsum `opt_w1` +4.81 % (nangate45) and +2.70 % (nangate15), vecadd `opt_w1` +2.77 % on nangate45. The mirror of the small sizes: the 64-beat run's fixed cycles, spread over 64 beats, are charged again on every one of 512 beats (vsum `opt_w1`: 66 cycles for 64 beats, 514 for 512).
- **axpy opt drives TVALID during reset** (Q7): harmless in hardware, a false beat in a TB that samples before reset is released.
- **vsim is slower on nangate15** (max 16.0 s against 6.5 s; sum 665 against 502 s). Its cell models use sequential UDPs, nangate45's `always` blocks (step 0's cell-model table); not traced further.

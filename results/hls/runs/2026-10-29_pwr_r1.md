# Run note: power r1, sim/pwr.py on tier done's vecadd, nangate45, 29 Oct 2026

The step 0 probe turned into a driver (`sim/pwr.py`, `docs/power.md`) and run on the 18 points of `done/vecadd/*` on nangate45: tb.json from hls-exercises' Verilog and params.json, rand64 stimulus at 64 beats, a functional zero-delay Questa simulation of each mapped netlist in `syn/runs/hls/nangate45/`, the busy window through vcd2saif into a SAIF, and PrimePower on the same netlist. No resynthesis; nothing under `syn/runs/` was written. All 18 points pass every check. The setup check passes on nangate45; on nangate15 it failed the 0.1 % rule on combinational (+1.95 %) and passes under X10 as amended after this run (2.5 % for that group, PT the reference tool). Repos: snax-forge-experiments from `642f768` (the driver is this round's work), hls-exercises `f530dfb`. Decisions X8, X9 and X16 rewritten, X18 to X20 new; pitfalls DC5, Q6, PT5 and E1 new.

## Commands

```bash
git pull --ff-only                                    # both repos up to date and clean
rm -rf sim/runs                                       # 50M of step 0 scratch; syn/runs/ untouched
```

## Odd things

- **The SAIF check first skipped entries it could not parse (PITFALLS DC5).** vcd2saif writes `(TZ t)` between TX and TC for nets at Z; the first regex wanted TC right after TX and dropped those entries without error, so T0 + T1 + TX = DURATION was never tested on them. They are undriven bits that DC left in declared vector wires (2044 of 25167 entries in `unopt_w32`, 2043 of them `zext_ln170_reg_255`; `b_fu_76[1]` in `opt_w8`, whose flop drives only QN), Z for the whole window and not nets in PT. The check now parses TZ, counts all-Z entries apart, fails partial Z, and fails when it parses fewer entries than the SAIF holds. Tested on corrupted copies of opt_w8's SAIF (a wrong T0, partial Z, clock TC 131, an unparsable entry): each fails. Every run was redone afterwards with identical numbers.
- **`$dumpon` at the window's falling edge lost that edge (PITFALLS Q6).** The first build put `$dumpon` / `$dumpoff` on the window's boundaries: `ap_clk` TC 131 for 66 cycles, caught by X9's clock check. Dumping now runs from the edge raising `ap_start` to the done edge, and `vcd2saif -time` cuts the window; TC 132 and step 0's numbers.
- **nangate15 failed the 0.1 % setup check** (above, PITFALLS PT5); it passes under the amended X10.
- **unopt's flops cost mostly clock-group energy.** unopt_w8: e_clk 7.61 of e_flop 8.90 pJ per cycle; its 1841 flops hold their value most cycles (26 cycles per beat). So e_bit falls with W for unopt (0.00722 to 0.00426 pJ) and rises for opt (0.01137 to 0.01559) and dace (0.01054 to 0.01522), whose data registers load every cycle. Per beat, unopt_w32's flops cost 2697.66 pJ against opt_w32's 34.04.
- **unopt's e_comb_pj is not monotonic in W:** 1.8714 at W = 16, 1.6775 at W = 32 (per cycle; per beat it still rises, 93.60 to 164.42).
- **dace costs one cycle more than opt from W = 4** (67 against 66) and, per cycle, about the same energy (dace_w32 45.48 against opt_w32 45.92 pJ) with 2 % more flops.
- **vcd2saif on PATH is DC's** (Y-2026.03-SP2); step 0 used PT's (W-2024.09-SP4-1). Forge on opt_w8 matches P1s to the printed digits; rand64 is -0.02 % from P2s, all of it in combinational (3.2465 against 3.2498 pJ). Not traced.
- **PT counts more nets than the SAIF has driven entries on flat netlists** (opt_w16: 6707 annotated, 6704 driven entries) and far fewer on hierarchical ones (dace_w32: 13262 against 25601, a SAIF entry per scope). Coverage is taken from PT only.
- **`pixi run python -c "..."` strips inner quotes** (PITFALLS E1); scratch analysis ran from files.
- `lmutil` is not on PATH in this non-interactive shell (PITFALLS L3), so `LMUTIL` was set.

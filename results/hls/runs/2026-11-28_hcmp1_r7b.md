# Run note: HCMP1 R7b, the Vitis and Bambu points of matvec_col and tier A (mvt, bicg, atax, gesummv), 28 Nov 2026

R6 wrote five kernels at X118's spec in hls-exercises (int8 in, int32 out, W = 8), each in forge's stream order with no more storage than forge's engine: `untiered/matvec_col` (m64_n64, matvec's column form) and tier A's `mvt`, `bicg`, `atax` (m64_n64) and `gesummv` (n64). This round builds and simulates their Vitis `opt` and Bambu points and writes the reports. Synthesis and power are R8's.

No testbench needed a port fix.

- **Outputs.** Every cycle run checks every output: matvec_col 0 of 64 lanes differ, bicg 0 of 128 outputs, atax 0 of 64 lanes, gesummv 0 of 64 results. The testbenches from dslx-exercises (with `str_src`) met Bambu's ports as they are: no port name was changed.
- **mvt.** Bambu's clang front end stops in its customSROA pass, which partitions an 8-element `ac_int` array completely (`[CSROA] ... alloca [8 x %class.ac_int.0] => [complete, 8]`) and then fails: `fatal error: error in backend: Unsupported use of an array-partitioned object (reportUnsupportedAccess:861)`. The row stays `failed: compile` (fail reason "Error in compilation") in hls-exercises' `results_staging/bambu_cycles.csv`; its log is `build/a/mvt/w8/bambu.log` (not kept in git).
- **The loop.** At 2026.11's default Bambu pipelines a loop it can: matvec_col's `BEAT` is tried at II 1 and 2 and refused; bicg's, atax's and gesummv's get no loop-pipelining line at all. Their `BEAT` bodies branch on a row's first and last beat (the per-row scalars, the results), which leaves the loop more than one basic block; the per-beat cycles (2 to 4) are what the FSM takes. Not changed here: the round keeps Bambu's rows as built.
- **bank and buf.** Bambu built no memory module (no `# ram:` line in any `filelist.f`, no BRAM module in the Verilog); the bank and atax's buffer are `register_SE` registers. Register bits per design: matvec_col 1,002, bicg 3,828 (103 of 32 bits, the bank's 64 int32 sums among them), atax 4,917 (the bank and the 8-beat buffer), gesummv 673.

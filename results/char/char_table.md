# CHAR1: snax-forge's blocks alone (int64)

Generated by `report/char_table.py` (`pixi run char-table`) from `results/char/<tech>/char_synth.csv` and `char_power.csv`; the known limits also read the files they cite. Do not edit by hand.

- **Commits:** snax-forge `e8611d51d5653e4c6e246184831136ec363727f5` (every row); snax-forge-experiments `6c727da448a1f0b9a18d10e875c9f3fe8c6b5faa` (the commit that wrote the power CSVs).
- **Settings:** clock 10 ns; synthesis as SYN1 and SYN2 (X1 to X4, X22; the block as top, X30); power rand64 seed 0, 128 cycles per window (SerialAccumulate's busy: 128 beats of W cycles), inputs at the rising edge, a lead-in slot before each window, the VCD cut per window (X31, X32).
- **Units:** area µm²; energy pJ per cycle of the window (e_comb, e_flop = clock + register + sequential, e_dyn = the two); e_bit and e_hold fJ per flop per cycle.
- **Windows:** busy (a fire every cycle) and idle (the enable at 0, every other input held) for ElementwiseLanes, Mac, TreeAccumulate and SerialAccumulate; stream for LinkBuffer (a load every cycle at full occupancy), a link that is not loading costing its flops x e_hold (X33).

## Model

The table snax-forge reads is `results/char/<tech>/char.json` (`report/char_export.py`, `pixi run char-export`; X37). Registers are bits: a flop that loads costs e_load per cycle, one that holds e_hold; a block keeps its comb part per fire (its busy window's e_comb; LinkBuffer's stream, per load); ctrl is its flops x e_hold x a counter factor. Per unit and task, with C_acc the task's cycles:

$$E_{\mathit{unit}} = n_{\mathit{fire}}\thinspace\big(e_{\mathit{comb}} + n_{\mathit{bits}}\thinspace(e_{\mathit{load}} - e_{\mathit{hold}})\big) + C_{\mathit{acc}}\thinspace n_{\mathit{bits}}\thinspace e_{\mathit{hold}}, \qquad E_{\mathit{ctrl}} = f_{\mathit{ctrl}}\thinspace n_{\mathit{bits}}^{\mathit{ctrl}}\thinspace C_{\mathit{acc}}\thinspace e_{\mathit{hold}}$$

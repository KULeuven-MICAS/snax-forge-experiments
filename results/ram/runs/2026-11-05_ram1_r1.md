# Run note: RAM1 R1, CACTI 7 at 45 nm, SRAM bank area and energy per access, 5 Nov 2026

CACTI 7 built from source, `ram/ram.py` turns (depth, width) into a CACTI config, runs it and parses it; 34 points ran: the 25-point grid (depths 16 to 256, widths 8 to 128), the check points 512 x 64, 2048 x 64, 128 x 256, 128 x 40 and 128 x 39 (padded to 40), the Horowitz points 1024 x 64 and 4096 x 64, and two variants of 512 x 64 (CACTI's default objective; ECC on). Results in `results/ram/nangate45/ram_cacti.csv`.

**28 points ok, 6 failed: CACTI does not model under 64 bytes (16 x 8, 16 x 16, 32 x 8) or a depth of 16 (any width); 32 words is its smallest depth. 512 x 64 at 1.1 V: 13,523 µm², read 3.54 pJ (55.3 fJ per bit), write 6.47 pJ (101 fJ per bit), access 0.269 ns.** Every point runs in about 0.2 s; the whole set in 1.2 s.

## ram.py and the config template

`pixi run ram point <d> <w>` runs one point and prints the parsed row; `pixi run ram all -j N` runs R1's points and writes the CSV (`ram/README.md`). A point's folder is `ram/runs/cacti/d<d>_w<w>[_<tag>]/` (git-ignored) with `cacti.cfg`, `cacti.out`, `cacti.err`, CACTI's own one-line summary `cacti.cfg.out`, `rc`, `time_s` and `key.json` (the config and CACTI commit: unchanged means not rerun; a second `all` reran nothing).

The config is CACTI's `cache.cfg` with these lines replaced (every other line as in `cache.cfg`):

Width: CACTI works in bytes, so a width that is not a multiple of 8 is padded up (`width_cacti`); 128 x 39 (the icache tag) runs as 128 x 40 and its row equals 128 x 40's in every number; its per-bit energies divide by 40.

Parsed by label from the summary block of `cacti.out`: `Access time (ns)`, `Cycle time (ns)`, `Total dynamic read energy per access (nJ)`, `Total dynamic write energy per access (nJ)`, `Total leakage power of a bank (mW)`, `Total gate leakage power of a bank (mW)`, `Cache height x width (mm)`, `Best Ndwl`, `Best Ndbl`, `Best Nspd`, `Best Ndcm`, `Best Ndsam L1`, `Best Ndsam L2`, `Data array: Area (mm2)`, `Area efficiency (Memory cell area/Total area)`. CACTI prints no total-area line for a `ram`: `area_um2` is height x width, equal to the data array area to 5 digits (no tag array). `leak_uw` is the subthreshold line; CACTI's `cacti.cfg.out` gives "Standby leakage per bank" as the sum with gate leakage (512 x 64: 2.33252 + 0.16359 = 2.49611 mW). A point fails when rc is not 0 or the summary is missing: CACTI's "Cache size must >=64" goes to stderr with rc **0**, so rc alone would pass it.

## Voltage

`tech_params/45nm.dat`: `-Vdd (V) 1 1.1 0.7 1.1 1.1` (hp, lstp, lop, lp-dram, comm-dram), so itrs-hp is 1.0 V. CACTI's normal output prints no Vdd. With `-print option - "debug detail"` it prints every tech table it loads (results identical to the run without it); `ram.py all` runs this once (`ram/runs/cacti/vdd_check/`) and stops unless every `-Vdd[0]` line (itrs-hp) is 1.0: 24 lines, all `-Vdd[0]: 1 (V)`. The data peripherals (`peri_global`, from the configured peripheral type) and the SRAM cell load flavor 0. The 1.1 V lines are flavor 1 (lstp: `sleep_tx`, the power-gating sleep transistor, power gating off) and flavor 3 (lp-dram: `dram_wl`, DRAM wordlines), neither on an SRAM `ram`'s path.

Every dynamic energy is scaled from 1.0 V to Nangate 45 nm's 1.10 V by (1.1 / 1.0)² = 1.21: `e_rd_pj`, `e_wr_pj`, `e_rd_bit_fj`, `e_wr_bit_fj`; the raw 1.0 V values are `e_rd_raw_pj` and `e_wr_raw_pj`. Area, timing and leakage are CACTI's, unscaled (leakage at 1.0 V, 300 K).

The failures (all of their error lines):

- 16 x 8, 16 x 16, 32 x 8 (16, 32 and 32 bytes), stderr, rc 0: `Cache size must >=64` (`io.cc:2048`).
- 16 x 32, 16 x 64, 16 x 128, rc 1: `ERROR: no valid data array organizations found`. Cause: `calc_subarr_rc` needs Ndwl ≥ 2 and Ndbl ≥ 2 (a mat is 2 x 2 sub-arrays) and `MINSUBARRAYROWS` = 16 rows per sub-array, and for a `ram` Nspd starts at `out_w / (8 · block_sz)` = 1, so rows per sub-array = d / (Ndbl · Nspd) ≤ d / 2: the least depth is 32.

## Checks

### 512 x 64 against R0 and D154

| | per 64-bit access | per bit | against CACTI read |
|---|---|---|---|
| CACTI read (1.1 V) | 3.54 pJ | 55.3 fJ | 1 |
| CACTI write (1.1 V) | 6.47 pJ | 101.1 fJ | 1.83 |
| snax-forge D154 placeholder (4 · e_load, nangate45) | 4.40 pJ | 68.68 fJ | 1.24 |
| OpenRAM R0, as DC charges it (11.51 pJ per cycle) | 11.51 pJ | 179.8 fJ | 3.25 |
| OpenRAM R0, P / f (57.55 pJ per access) | 57.55 pJ | 899 fJ | 16.3 |

D154's placeholder sits between CACTI's read (0.80 x D154) and write (1.47 x D154); the mean of read and write is 78.2 fJ per bit, 1.14 x D154. OpenRAM's figure, read as the energy of an access, is 16.3 x CACTI's read and 8.9 x its write: consistent with R0's finding that it counts every gate of the macro switching at 100 MHz.

### Horowitz, ISSCC 2014 (45 nm, 0.9 V)

Horowitz's table ("Computing's energy problem", 45 nm, 0.9 V) gives a 64-bit read at about 10 pJ from an 8 KB SRAM and 20 pJ from 32 KB.

| point | size | CACTI read 1.1 V | at 1.0 V (raw) | at 0.9 V (raw · 0.81) | Horowitz | CACTI 1.1 V / Horowitz |
|---|---|---|---|---|---|---|
| 1024 x 64 | 8 KB | 6.40 pJ | 5.29 pJ | 4.28 pJ | about 10 pJ | 0.64 |
| 4096 x 64 | 32 KB | 18.06 pJ | 14.92 pJ | 12.09 pJ | about 20 pJ | 0.90 |

CACTI is below Horowitz's rounded figures at either voltage (0.43 and 0.60 of them at his 0.9 V), and grows faster with size (2.8x from 8 to 32 KB against his 2x). Same order of magnitude; Horowitz's figures are rounded and from unstated macros.

### Area density

512 x 64: 32,768 bits in 13,523 µm², 2.42 Mb/mm² (10⁶ bits; 2.31 Mib/mm²), 2.9 x OpenRAM's published 0.826 Mb/mm² at FreePDK45. Over the ok points 1.08 (32 x 128) to 2.76 Mb/mm² (4096 x 64): density rises with size and falls for wide, shallow arrays, whose periphery (sense amps, drivers per column) is a larger share (area efficiency 31.9 % at 32 x 128, 81.7 % at 4096 x 64). CACTI's SRAM cell is 146 F² = 0.2957 µm² at F = 45 nm (`45nm.dat`'s SRAM `-area_cell`, in F² despite its "um^2" label, multiplied by F² in `parameter.cc:611`); area efficiency x area / bits gives 0.2956 µm² on every point.

### Smoothness across the grid

Area, read energy, write energy and access time rise monotonically with depth at every width and with width at every depth: no drop anywhere in the grid (checked by script on the 19 ok grid points). What is not smooth:

- **The organization.** Every ok point has Ndwl = Ndbl = 2 (one mat, CACTI's minimum) and Ndsam L1 = 1; only Nspd (and Ndcm with it) changes: Nspd 1, Ndcm 2 everywhere at depths 32 and 64 and at 128 for w ≥ 16; Nspd 2, Ndcm 4 at 128 x 8 and at 256 for w ≤ 64, and at 512 x 64; Nspd 1 again at 256 x 128; Nspd 4 at 1024 and 2048 x 64, Nspd 8 at 4096 x 64. Each sub-array is then d / (2 Nspd) rows by w · Nspd / 2 columns.
- **Energy per bit.** Read per bit is about flat with width at depths 32 and 64 (20.7 to 25.8 fJ) and rises with depth (bitline length): 22.8, 27.1, 44.5 fJ at w = 64 for d = 64, 128, 256. Where Nspd is 2 (w = 8 at d = 128 and 256) the narrow widths cost more per bit (41.2 and 59.1 fJ against 33.3 and 48.8 at w = 16). At 256 x 128 Nspd falls back to 1: read per bit drops to 34.8 fJ while write per bit jumps to 92.0 fJ.
- **Write against read.** Write / read is 1.24 to 2.64 (2.64 at 256 x 128; 1.84 to 2.03 at depth 128 for w ≥ 16, but 1.25 at 128 x 8, where Nspd is 2); at 4096 x 64 write is below read (15.35 against 18.06 pJ, 0.85), the only such point.
- **Same sub-array, same timing.** Points with the same sub-array shape have identical access and cycle times to six digits: 512 x 64 and 256 x 128 (both 128 x 64 sub-arrays: 0.268994 and 0.210011 ns), 64 x 16 and 128 x 8, 128 x 16 and 256 x 8, and so on; their energies and areas differ.

For R2's fits: energy per access is close to linear in w at fixed d, and a fit in d needs to absorb the Nspd steps (or be fitted per Nspd). Depth 16 needs a rule of its own (CACTI cannot model it).

## CACTI's own objective and ECC (512 x 64)

| 512 x 64 | objective | area µm² | E_rd pJ | E_wr pJ | t_access ns | t_cycle ns | leak µW | Nspd, Ndcm, Ndsam L1, L2 |
|---|---|---|---|---|---|---|---|---|
| ours | 0:50:0:0:50 | 13,523 | 3.538 | 6.468 | 0.26899 | 0.21001 | 2,333 | 2, 4, 1, 1 |
| CACTI's default | 0:0:0:100:0 (cycle time) | 13,690 (+1.2 %) | 4.037 (+14.1 %) | 6.378 (-1.4 %) | 0.26886 (-0.05 %) | 0.20768 (-1.1 %) | 2,341 (+0.4 %) | 2, 1, 1, 4 |

CACTI's default objective (cycle time only) moves the column multiplexing from the bitline mux (Ndcm 4 to 1) to the sense-amp mux (Ndsam L2 1 to 4): read energy +14 % for a 1 % shorter cycle; area and write energy barely move. ECC adds about 12.5 % (one bit in 8) to area, energy and leakage, as its rule says.

## Odd things

- Cycle time is below access time on every point (512 x 64: 0.210 against 0.269 ns): CACTI's random cycle time does not include the full output path.
- Leakage is large for itrs-hp at 300 K: 2.33 mW for 4 KB (71 nW per bit); in the detailed power block "Total leakage power in cells (mW)" is 22 (more than the bank's 2.33 total) and the row and column logic leakage print 6.91503e-307 (an uninitialized value). Only the bank total is parsed; leakage is not used by HWCOST yet.
- Every run also prints a DDR3 off-chip IO model (`IO Area (sq.mm) = inf`) and a MemCAD block (80 GB, 533 MHz) from `cache.cfg`'s IO and MemCAD lines; they are not about the RAM and are not parsed. `Tag size : 42` is printed for a `ram`, which has no tag array.
- "Cache size must >=64" exits with rc 0 and no summary.
- CACTI loads tables of all five device flavors; only the 1.0 V itrs-hp ones are on this path (Voltage).

## PITFALLS

# Run note: SYN2 R1, SYN1's 48 forge points rebundled from CTRL1 and resynthesized on nangate45 and nangate15, 2 Nov 2026

SYN2 measures SYN1's forge points again after snax-forge's CTRL1 (KULeuven-MICAS/snax-forge#48: `<tag>_csr` as the interface, D152; nested group counting without products, D153), with SYN1's flow and settings. ## Step 2: the bundles

```bash
pixi run forge-rtl done/dot/forge3_w4      # alone first: the Emit classpath was older than CTRL1's Scala sources
pixi run forge-rtl -j 32                   # all 48
```

- **The first point alone.** snax-forge's `hw/chisel/target/emit-classpath.txt` existed (from before the checkout of main), but files under `hw/chisel/src/main/` were newer, so the first Emit recompiles with sbt. `forge/bundles.py` runs a first point alone only when the file is missing, so parallel first calls would have raced: `done/dot/forge3_w4` ran alone first (31 s, the classpath re-exported), then all 48 (48 made, 0 refused, 0 failed, 41 s of wall time).
- Every `point.json`: `snax_forge_commit` `f9764d5c2f434183f1bed3678a5aa260a4c1d9c1`, `dirty: false`. snax-forge's tree stayed clean.
- **Against SYN1's bundles** (`rtl/forge_syn1/`), per point, `rtl/sv/` byte for byte: every point changed in exactly four files, `snax_forge_csr.sv`, `snax_forge_ctrl.sv`, the group's control unit (`snax_forge_acc_ctrl.sv` for vecadd, vecmul and vsum_tree, 18 points; `snax_forge_dot_ctrl.sv` for dot 2 to 6, 30 points) and `snax_forge_shell_wrapper.sv`. No datapath file changed, no file was added or removed, and `bundle.json`'s `modules` are identical in all 48.

## Step 3: synthesis

```bash
pixi run syn run 'done/*/forge*' --source forge --tech nangate45 -j 8 --cores 3
pixi run syn run 'done/*/forge*' --source forge --tech nangate15 -j 8 --cores 3
```

- 48 rows per technology in `synth_dc.csv`, 672 in `synth_dc_modules.csv` (as SYN1), all `ok`.
- Glue: 0.53 to 1.60 µm² on nangate45, 0.15 to 0.30 µm² on nangate15, at most 0.058 % of a total; none negative, none above 1 %.
- **Flops** (`seq_cells`): 32 fewer at every point (START's register is now a strobe, D152), 96 fewer for dot 3 at every W (also its two 32-bit counters, D153), on both technologies.
- **csr grows, ctrl shrinks, the datapath stays.** Over the 48 points csr changes by +3.4 % to +7.9 % on nangate45 and +4.3 % to +6.7 % on nangate15 (STATUS's done bit and COUNTER now live there); ctrl by -13.6 % to -67.7 % and -14.7 % to -69.4 % (dot 2 and 3 lose the 32 × 32 multiplier, dot 3 two counters). The total falls by 0.09 % (dot 4 W = 32) to 20.7 % (dot 3 W = 1) on nangate45 and 0.08 % to 20.1 % on nangate15.
- **The datapath's SV is unchanged, its area moves by DC's noise:** at most 21.3 µm² (-0.068 %, dot 2 W = 4) on nangate45 and 0.93 µm² (-0.002 %) on nangate15; the largest share is -0.127 % (dot 2 W = 2, 20.2 µm²). Boundary optimization is on (X22), so DC's choices in the datapath can follow its changed neighbours.

# Run note: SYN1 R0, the forge driver, `syn.py --source forge` and the probe, 31 Oct 2026

SYN1 compares snax-forge's generated accelerators with the HLS points of `results/hls/` (area and dynamic energy, forge's control and datapath apart). This round builds the driver that bundles the 48 forge points (`forge/bundles.py`, `pixi run forge-rtl`), teaches `syn/syn.py` the forge source, and synthesizes one probe point, `done/dot/forge3_w4`, on nangate45 and nangate15. The full sweep is R1.

## Step 1: the driver

- `forge/points.json`: the 48 points, `{"point", "recipe", "W"}` each. vecadd, vecmul, vsum_tree and dot_2 to dot_6, at W = 1, 2, 4, 8, 16, 32 (int64, the recipes' own dtype). Names: `done/vecadd/forge_w<W>`, `done/vecmul/forge_w<W>`, `done/vsum/forge_w<W>`, `done/dot/forge<k>_w<W>`.
- `forge/bundles.py`, pixi task `forge-rtl`: `[patterns] [--list] [--dry-run] [-j N] [--allow-dirty]`, plus `--set K=V` (more sandbox sets; they also tag the sandbox and design folders) and `--out DIR` (default `rtl/forge`), both for step 2. Per point, in `SNAX_FORGE` (default `../snax-forge`) through `pixi run --manifest-path $SNAX_FORGE/pixi.toml`: `sandbox recipes/<r>.json --set W=<w> --out out/sandbox/syn1/<r>_w<w>`, `design <the .snaxdfg with the highest numeric prefix> --platform platforms/snax_forge.json --out out/design/syn1/<r>_w<w>`, `bundle .../design_point.json --out rtl/forge/<point>/`. The point's folder, sandbox folder and design folder are emptied first. Every task's output goes to `rtl/forge/<point>/forge-rtl.log`. A failed task prints its last 25 lines.
- **The inner pixi.** The inner runs get the environment with every `PIXI_*` and `CONDA_*` variable removed and PATH without this repo's `.pixi/` entries. Before any point, the driver runs `printenv CONDA_PREFIX` through the inner pixi and stops unless it is under `$SNAX_FORGE/.pixi/envs/`. Checked by hand from inside `pixi run`: with the cleaned environment, `sys.prefix` is `snax-forge/.pixi/envs/default`, `snax_forge` is imported from the checkout and `sbt` is that environment's. With the outer environment left as is, pixi 0.46 also lands in snax-forge's environment, but warns `Using local manifest .../snax-forge/pixi.toml rather than .../snax-forge-experiments/pixi.toml from environment variable PIXI_PROJECT_MANIFEST`; the cleaning makes this independent of pixi's precedence.
- **Dirty bundles.** A `bundle.json` with `dirty: true` is refused: the folder is emptied but for the log, so `syn list --source forge` does not see it. `--allow-dirty` keeps it. This was checked with the bundle step stubbed to write `dirty: true` (snax-forge not touched): refused, then kept with the flag. Kept bundles get `point.json` (point, recipe, W, `snax_forge_commit`, `dirty`, `sets`, date).
- `rtl/` is in `.gitignore`.
- **All 48:** `pixi run forge-rtl -j 6`: 48 made, 0 refused, 0 failed, in 68 s of wall time (the points took 7.9 to 9.4 s each, 404 s in sum). Every bundle is `snax_forge_commit` `520a5661802acb9967d8bca43201de60b43006cd`, `dirty: false`. No task printed an error. The first point alone (`done/dot/forge3_w4`, with the classpath export) took 28.5 s.

No HLS point was rerun.

## Odd or open

- Both first DC tries failed with licence error -92 (L1) and passed on the X17 retry.
- `failed: no area report` is what syn.py writes for a licence failure; a licence-aware status would change the HLS path too, so it is left for a later round.
- The output inverters at the wrapper's level mean csr + ctrl + datapath is slightly below the top (0.006 % / 0.003 %). R1 can keep the top's own level as a separate "glue" share or set `set_boundary_optimization false` on the three modules; this round changed neither.
- The 64-bit multipliers in `ElementwiseAlu_w64_mul` are unregistered, so forge's flop count is less than half of HLS's and its `fmax` lower bound is lower. At 10 ns both meet timing.
- DC ran on 7 cores (host load); this changes only the run time.

# Run note: CSYN1 Part B R3b, the cluster's area in groups against HWCOST, 11 Nov 2026

R3 (`2026-11-11_csyn1_r3.md`) synthesized `dot3_w16` (dot_3 at W = 16, N = 2048) as a whole cluster and kept its `area_hierarchy.rpt`; R3d (`results/xbar_mix/runs/2026-11-11_csyn1_r3d.md`) compared HWCOST's five parts with it by hand. This round makes that comparison a script on the committed reports (X72): the cluster's area in groups, HWCOST's parts against the groups that hold them, and the accelerator's shell against its point synthesized alone. Done in chat; no tool run on the server. HWCOST was priced in Claude's sandbox with snax-forge main `b19b9262` (#68, X71's factor form) through `SNAX_FORGE_PYTHON` (a venv with snax-forge installed, no pixi there).

**Result:** the five parts HWCOST prices are 825,985 µm² of the cluster's 1,314,306 (62.8 %); HWCOST gives 826,287 µm² for them (+0.04 %), each part within 11 % (datapath 0.0 %, control −5.7 %, streamers −6.6 %, crossbar +10.8 %, memory 0.0 %). The other 488,321 µm² (37.2 %) are what HWCOST does not cost: AXI 14.0 %, DMA 6.2 %, TCDM bank logic 4.3 %, cores 4.1 %, I-cache 6.7 % (logic and macros), peripherals 1.4 %, the CSR path and the accelerator's csr 0.4 %. The accelerator's shell in the cluster is within 0.04 % of the same point synthesized alone (`done/dot/forge3_w16`).

## What was built

- `cluster/groups.json`: the groups and their rules (a regex on the instance path, and on the design name for the macros); a node takes the first group with a matching rule, else its parent's; its own area goes there, so the groups add up to the total. `hwcost` maps the five parts to groups.
- `cluster/hwcost.py` (`pixi run cluster-hwcost <point>`): snax-forge's estimate for the point's recipe, W and sets on `platforms/snax_forge.json`, run in snax-forge's environment (it calls itself there with `--inner`), written to `results/cluster/nangate45/hwcost/dot3_w16.json` with the commit and a clean flag.
- `report/cluster_breakdown.py` (`pixi run cluster-breakdown [--md]`): `results/cluster/nangate45/breakdown.json`; the macros checked against `synth_dc.csv`'s `macro_um2` (475,790.89 against 475,790.89, ok). Test `report/test_cluster_breakdown.py` (`pixi run cluster-breakdown-test`, 5 tests on a made-up hierarchy and the real groups file, all ok).
- `cluster/points.json`: `dot3_w16` gets `"alone": "done/dot/forge3_w16"`; nothing in `cluster.py` reads it, and the bundle's reuse key does not include it.

## Observation, not acted on

The TCDM bank logic (32 AMO shims at about 1,590 µm² each and 4 muxes, 55,965 µm²) is 12.9 % of the banks' macro area and sits beside every bank. HWCOST's memory part is the macros alone (D160). If the evaluation compares designs with different bank counts, a per-bank logic term would follow them; with one bank count it is a constant and changes no comparison.

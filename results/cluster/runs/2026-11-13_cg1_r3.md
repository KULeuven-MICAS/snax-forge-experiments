## Reading (short, for Ryan)

- The floor was clocking: with 98.6 % of the registers behind a gate, the idle floor falls from 376.7 to 31.5 pJ per cycle. What is left is mostly registers DC could not gate or that run anyway: the peripherals (7.1, the same in every window: always-enabled counters), AXI (7.1, 266 one-bit registers below the minimum), the core (3.6, its polling loop), the DMA (3.4), the sparse interconnect (2.7, up from 2.1: 140 always-enabled registers and nothing to gate, with a slightly different netlist around it).
- With the floor gone, the run window and "above idle" nearly meet (49.48 against 47.79 nJ for the five parts, against 64.09 and 36.53 ungated): the gated run window is almost all activity, which is what HWCOST prices.
- The part gating changes is the streamers: 26.28 → 11.88 nJ in the run window (ungated, their run was below their idle, −0.31 above idle). The datapath, crossbar and memory are busy every cycle of the run and barely change.
- HWCOST is now above the gated netlist on three parts: datapath +64 %, streamers +71 %, crossbar +40 %; memory equal. The datapath gap is not from gating: it was there ungated (24.25 against 14.91), and the shell alone with rand64 data runs at 92.72 pJ per cycle against 46.85 in the cluster with the program's data. HWCOST's per-beat tables come from blocks synthesized and powered alone, ungated (CHAR1, STRM1), so their cost per beat holds each block's own clock while busy; a gated cluster against HWCOST like for like would want gated tables too, which `syn.py --clk-gate` and `pwr.py --clk-gate` (X79) can now make.
- Register energy rises and combinational falls in every window (run: e_reg 8.6 → 16.5, e_comb 104.9 → 97.1 pJ/cycle). With the enable mux gone, a gated flop's D pin follows its logic every cycle even while its clock is stopped, and PT books a flop's D-pin internal energy under register; before, the mux held D steady and its toggling was combinational. X11's e_clk + e_reg is the flop's energy either way.

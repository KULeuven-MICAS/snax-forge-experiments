Plus the plain RTL check on the worktree, `make snax-forge-check BUNDLES=<dot_3_W16_N2048> SIM=vsim SNAX_CLUSTER_IMAGE=c5db84ad7bce`, with no `SIM_TYPE`: PASS, 828 cycles.

Why run 2's RAMCOUNT failed:

1. **The parse (PITFALLS Q15).** The netlist printed all 36 RAMCOUNT lines, but their paths hold DC's escaped identifiers, each ending in a space (`...i_snitch_data_mem.\gen_banks[0].i_data_mem .\gen_sram_d512_w64_m8.i_macro  sram_d512_w64_m8 reads 139 writes 139`), and the regex took the path as one token: 0 lines read.
2. **The time-0 write (PITFALLS Q14).** Compared by instance, with the paths normalised: the 32 TCDM banks equal, every macro's reads equal (487 on the I-cache's), but the I-cache's 4 macros (2 data `sram_d128_w256_m8`, 2 tag `sram_d128_w39`) count 238 writes against 237. The diagnostic put the extra write at time 0, with `rst_ni` low and `addr_i` = `7'h7f`, in all four at once. The RTL run has none there: its `req_i` is X at time 0, and RAMCOUNT counts `=== 1'b1`. The most likely cause is Q8 (nangate45's flops start with Q and QN both 0 under `+initreg+0`, so logic that reads a QN sees 1 until the first clock edge); not traced net by net. Harmless: reset is held, and the flush rewrites every line during reset (32 cycles of writes in the netlist, 31 in the RTL).

The decision (Ryan): keep RAM1's models (`ram/ram.py`) as they are, since the model text is part of the macro cache key and a change would rebuild every macro; the check allows exactly one more write on an instance of the netlist run. `ram_compare` now matches instances per macro by their counts (equal (reads, writes) first, then the netlist's (r, w) to the RTL's (r, w - 1)). Every such instance goes into `gls/check.json` as `ram_extra_writes` (macro, reads, RTL and netlist writes) and into the summary line. Two or more extra writes, fewer writes, any read difference, or an instance missing or added fail; there is a test for each, and one from R4's real lines.

**Unexplained, not chased:** the diagnostic's trace placed one write to the I-cache's tag set 1 at 255 ns in the RTL and at 1,274 ns in the netlist, each with no partner in the other run. The same trace counts one write fewer on that macro than the model's own RAMCOUNT in both runs (236 against 237 in the RTL, 237 against 238 in the netlist, the time-0 one included). The trace samples the ports at the wrapper's clock edge from a `when` handler, so the most likely reading is the delta order of that sampling against the macro's own clock (which, in the netlist, comes through the clock tree's buffers). The models' own counts agree on that macro once the time-0 write is set aside.

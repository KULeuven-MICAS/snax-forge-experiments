**All 17 runs ok, every reference check equal and every sink at 0 mismatches. The W = 32 points' cycles equal their ungated twins'; `counter_diff` and `expected_diff` are 0 on all 17. ctrl/ctrl at W = 32 is within 1 to 4 % of the kernel's W = 16 point for vecadd, vecmul, vsum, dot 2 and dot 4, and 11 % below it for dot 5 and dot 6; f_ctrl over the 48 int64 points would be 83.20 (82.87 on the 41). ### What the power flow needed (X90)

The flow refused a narrow bundle at three places; each now follows snax-forge's own rule (D142: a 64-bit word packs num_slc = 64 / bits elements little-endian; D174: a packed output's word holds d_out results, sent full or at the run's last push, the slices past the last one 0).

- **`forge/query.py program`** refused `num_slc 8; only one element per channel word is mapped`. It now walks the streamer's addresses in words (snax-forge's `word_bounds`) and gives each word's num_slc element slots, -1 for a packed word's empty slice; a stream also carries `num_ch`, `num_slc`, `d_out`, `dtype`. **`point`** also returns the design point's dtypes (containers and type parameters), so the reference runs at the preset's types (`types=i8` reaches the bundle through the sets, not `point.json`'s `dtypes`).
- **`sim/sources/forge.py`** took int64 ports with one lane per channel only, and read every set as a shape symbol (`types=i8` failed `int()`). It now takes int8 to int64, checks a wire-sliced port as lanes = num_ch x num_slc and a packed one as one channel of d_out results, writes `lanes` = the TB's 64-bit channels and `elems` = the element slots a beat, and the tb.json dtypes from `query.py point` under `point.json`'s.
- **`sim/pwr.py` `stimulus_forge`** drew full-range int64. It now draws each input full-range at its element dtype (X19's generator and seed; an int64 stream draws exactly as before), wraps the reference's outputs to the output dtype (int32), and packs elements into 64-bit words (`words`), a packed output's upper slice 0; the sink compares whole words, so the packer's zero fill is checked too.
- **`forge_ref_check`'s cache** was keyed by kernel, size, seed and pins (the inputs depended on N and the seed only), so in the first narrow batch the second dtype of each kernel was checked against the first's outputs and failed: `reference out differs from the batch's first dot run on the same inputs` at dot 4 and dot 5 i16, vecmul i16 and vsum i8 (whichever came second). The key now has the dtypes as well; those four were rerun and are ok. Their failed rows were replaced.
- An int64 point is unchanged: rebuilt for `untiered/axpy/forge_w1`, its stimulus words equal the committed run's and its tb.json gains only `num_slc`, `d_out`, `elems` = 1 and `ACC` in the dtypes. Test: `sim/test_forge_stream.py` (little-endian words, an int16 vsum with its packed output, the int64 draw unchanged).

## Anything odd

- **The packer's energy depends on what feeds it.** Behind vsum's tree and dot 3's tree (each beat's partial sum on the packer's input) it costs 0.13 to 0.22 pJ a cycle, 51 pJ a task at dot 3 W = 8, 3 % of the accelerator; behind dot 4's and dot 5's sum blocks (an output that changes once) 0.013 to 0.023. Its area is the same everywhere. The char point drives it with a push every cycle or none (X89), neither of which is this case.
- **CSV line ends.** `syn.py` and `pwr.py` write CRLF; forge's CSVs have been LF since the CG5 merge, so each batch rewrote every line. The four forge CSVs were turned back to LF before each commit; the diffs hold only this round's rows (PITFALLS E9).
- **forge-rtl's first point runs alone each time**, printing `no hw/chisel/target/emit-classpath.txt yet`: snax-forge now keeps one `emit-classpath-<hash>.txt` per environment, so `forge/bundles.py`'s check never finds the old name. It costs about 12 s a batch; not changed.
- **The bundles of the other 8 axpy and matadd points** (all but `forge_w1`) still have no `ACC` in their `point.json`; a power rerun of them needs a rebundle first (E8, amended).

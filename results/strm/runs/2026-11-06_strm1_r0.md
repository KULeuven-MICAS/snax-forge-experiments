## Power of the reader (step 3)

A zero-delay Questa TB on the mapped netlist (X7), `vopt +initreg+0 +acc=n`, `vsim +nospecify +notimingchecks`.
- **Stimulus:** reset for 5 edges, released at a falling edge. `io_start` is high for one cycle with `ptr` 0, spatial stride 8 B (one 64-bit word per channel), temporal strides 32 B and 1,024 B (C x 8 and b0 x C x 8: unit strides, the beats contiguous), bounds 32 x 32 = 1,024 beats.
- **TCDM model:** every request is granted at once (ready tied 1). The model samples the requests at the falling edge, and at the next rising edge drives the response valid with a new random 64-bit word, so the reader takes it one cycle after the grant. The output is always ready.
- **Window:** from a quarter cycle before the edge that takes `io_start` to a quarter cycle before the edge that takes the last beat, CHAR1's rule (X31), so no event sits on a boundary. It has 1,027 cycles.
- **Activity:** the VCD dumps the DUT's nets and its 39 sub-design scopes (`pwr.scopes`) from time 0. The window is cut out (`pwr.vcd_windows`, X32) and vcd2saif runs on the cut. Both VCDs are deleted at once (X18). PT runs `sim/scripts/pt_power.tcl` unchanged on `saif`, averaged mode, 8 threads.

Checks, all passed:
- Beats counted at the output: 1,024 = 32 x 32.
- The fill is 3 cycles from the start edge to the first beat, then 1,024 beats in 1,024 cycles: 0 stalls after the fill, and cycles = fill + beats.
- Every beat's 4 x 64 bits equal the responses in order per channel, channel 0 in the low bits: 0 mismatches.
- Every request address is 8 x (beat x 4 + channel): 0 mismatches. No X or Z on the outputs.
- SAIF (X9): DURATION 10,270,000 ps = 1,027 x 10 ns; clock TC 2,054 = 2 x 1,027; T0 + T1 + TX = DURATION on all 14,259 driven nets; 48 nets Z for the whole window (DC5's undriven wire bits), counted apart.
- PT: 9,275 of 9,275 nets annotated (100 %). Wire load: 0 nets with wire capacitance, 0 with resistance (PT1).

|---|---|---|---|---|---|---|---|---|---|---|
| streamer/d8_l2_c4 | 1,027 | 1,024 | 11.414 | 2.190 | 0.000 | 6.626 | 20.231 | 20,777.1 | **20.290** | 2.023 |

## Power of the interconnect (step 4)

The same flow.
- **Stimulus:** for each cycle t = 0..1023, input i requests bank (i + t) mod 32 (no two inputs on one bank) at a random row; `write` = t odd for every input, so reads and writes alternate every cycle. Write data is random, `strb` ff, `amo` 0, `priority` 0, `user` 0.
- **Memory model:** always ready. `memRsps_valid` is tied 1, as `sparse_interconnect_wrapper` ties it. A read bank's `memRsps_data` is a new random word at the next rising edge; `tcdmRsps_ready` is 1.
- **Window:** from a quarter cycle before the edge that applies cycle 0's requests to a quarter cycle before the edge after cycle 1,024, the last read responses' cycle. That is 1,025 rising edges.

Checks, all passed:
- Grants (`valid & ready` at the falling edge): 16,384 = 16 per cycle x 1,024, and every cycle granted all 16.
- Each bank's request (row, write, data, strb) equals its input's, and no bank is valid without an input: 0 mismatches.
- Each read response is valid the next cycle with that bank's data: 0 mismatches. No X or Z.
- SAIF: DURATION 10,250,000 ps; clock TC 2,050; all 128,723 driven nets good; 16 nets Z.
- PT: 70,243 of 70,243 nets annotated (100 %); wire load 0 and 0.

| point | cycles | grants | E_clk pJ/cyc | E_reg | E_seq | E_comb | E_dyn pJ/cyc | E window pJ | **E per access pJ** | P_dyn mW |
|---|---|---|---|---|---|---|---|---|---|---|
| xbar/i16_b32 | 1,025 | 16,384 | 1.192 | 1.019 | 0.000 | 47.577 | 49.787 | 51,032.2 | **3.115** | 4.979 |

The window's last cycle has no requests, only the last read responses (0.1 % of the cycles). The mix is half reads and half writes, so 3.115 pJ is the mean of the two.

**`sim/pwr.py --source streamer|xbar`.** The TB is generated per point, because the port names carry the channel and bank index. Everything after vsim is `pwr.py`'s own: `scopes`, `vcd_windows`, `saif_check(saif, cycles, "clock")`, `pt_power.tcl` unchanged (the run's `tech.json` carries `SYN_CLK_PORT clock` and `SYN_RST_PORT reset`), `coverage`, `wire_load_check`, `pt_groups`. The TB prints `TB: window busy t0_ns .. t1_ns .. cycles ..` and its check line. The reader TB's core:

```systemverilog
// config tied: ptr 0, spatial stride 8, temporal bounds B0, B1, strides 8*C, 8*C*B0; output ready 1, TCDM ready 1
always @(negedge clock) if (!reset) begin
    req_seen = req_valid;                                         // granted at the next rising edge
    for (int i = 0; i < C; i++) if (req_valid[i]) begin
        if (req_addr[i] !== 17'(8 * (n_req[i] * C + i))) addr_bad++;
        n_req[i]++;
    end
    if (in_run && !done) begin
        cycles++;
        if (data_valid) begin
            if (fill < 0) fill = cycles - 1;
            for (int i = 0; i < C; i++) begin                     // channel i in bits 64i +: 64
                if (q[i].size() == 0 || data_bits[64*i +: 64] !== q[i][0]) data_bad++;
                if (q[i].size()) void'(q[i].pop_front());
            end
            beats++;
            if (beats == BEATS) begin done = 1; t1 = $realtime + T_NS / 4; end
        end else if (fill >= 0) stalls++;
    end
end
always @(posedge clock)
    for (int i = 0; i < C; i++) begin
        if (rsp_valid[i]) q[i].push_back(rsp_data[i]);            // the DUT takes it at this edge
        rsp_valid[i] <= req_seen[i];                              // data the cycle after the grant
        if (req_seen[i]) rsp_data[i] <= {$urandom, $urandom};
    end
// sequence: 5 reset edges, release at a falling edge, 4 idle edges, start <= 1;
// @(posedge) (this edge takes io_start): start <= 0; t0 = $realtime - T_NS / 4; in_run = 1
```

The xbar TB's core:

```systemverilog
task automatic apply(input int c);                               // at the rising edge that starts cycle c
    for (int i = 0; i < N; i++) begin
        row[i] = MAW'($urandom);
        q_valid[i] <= c < CYC;
        q_write[i] <= c % 2;
        q_addr[i]  <= {row[i], BB'((i + c) % B), 3'b000};         // bank (i + c) mod B
        q_data[i]  <= (c % 2) ? {$urandom, $urandom} : q_data[i];
    end
endtask
always @(negedge clock) if (!reset && t >= 0 && t <= CYC) begin   // cycle t
    for (int i = 0; i < N; i++)                                   // cycle t-1's reads answered now
        if (t >= 1 && was_read[i] && (!p_valid[i] || p_data[i] !== m_rdata[was_bank[i]])) rsp_bad++;
    if (t < CYC) begin
        if ((q_valid & q_ready) !== {N{1'b1}}) grant_bad++;
        grants += $countones(q_valid & q_ready);
        for (int b = 0; b < B; b++) begin                         // bank b serves input (b - t) mod B
            ... m_valid, m_addr == row, m_write, m_wdata, m_strb checked; no valid bank without an input ...
            bank_rd_next[b] = (i < N && !q_write[i]) ? {$urandom, $urandom} : m_rdata[b];
        end
        ... was_read, was_bank for the next cycle ...
    end
end
// rising edge: m_rdata <= bank_rd_next; t++; apply(t). t0 a quarter cycle before cycle 0's edge,
// t1 a quarter cycle before the edge after cycle CYC: CYC + 1 cycles
```

The xbar TB needs inputs <= banks: with more inputs than banks, `(i + t) mod B` puts two inputs on one bank, as the kickoff has it (power only where inputs <= banks).

## Odd things (PITFALLS candidates)

- **The reader's module name has a double underscore.** `StreamerGen` sets `tagName` = `<tag-name>_`, and `Streamer` names reader i `tagName + "_C" + i`, so with `--tag-name strm` the reader is `strm__C0_Reader`. gen.py builds the name the same way and fails a point when the module is missing.
- **StreamerGen always writes a CSR header.** It writes `streamer_csr_addr_map.h` to `--header-dir` as a side effect of elaboration, so the argument is required; gen.py points it into `tmp/` and drops the header.
- **`git archive` leaves out submodules.** snax_cluster's `hw/chisel/build.sbt` depends on `hw/chisel_acc/subprojects/chisel-float`, a submodule. gen.py exports it separately from the submodule's checkout at the gitlink (`git ls-tree`) and refuses when that commit is not there.
- **`sbt -batch` stops at the first failing command.** One bad point stops the points after it in the same call. gen.py reports those as not run; the next call skips the made ones and generates the rest.
- **The image has no Scala caches of its own.** Mounting the home folder's caches made generation offline here; without them every call downloads sbt, Chisel and firtool, and about 70 such runs in a day got this host rate-limited by Maven on 2026-11-04. The mount points must exist, and gen.py creates them.
- **A count of `reg` declarations overstates the registers.** firtool's `ram_<d>x<w>` modules declare `_RANDOM_MEM` and the registers declare `_RANDOM` temporaries inside `ifdef ENABLE_INITIAL_*` blocks, which synthesis drops. Skip `_RANDOM*` when counting.
- **Temporal stride 0 is the reader's repeat mode.** `Reader` sets loop 0's bound to 1 and repeats each beat `temporalBounds(0)` times on the output (`HandShakeRepeater`). A TB with stride 0 gets a different beat count from the same bounds, so the TB uses nonzero strides.
- **Different reset kinds.** The reader is `RequireAsyncReset` (asynchronous, active high). `SparseInterconnect` is a plain `Module`: a synchronous, active-high reset. `dc_syn.tcl` keeps both ideal (`set_ideal_network`), and the TBs hold reset for 5 edges with the clock running.
- **The bundled reader is the reader as the Streamer uses it.** firtool elaborates the whole Streamer, and in a module that is not the top it removes the output ports the parent never reads and propagates the constants it ties. `strm__C0_Reader` therefore has no `io_bufferEmpty` port (Reader.scala drives it from `dataBuffer.io.allEmpty`, and Streamer does not read it), and its TCDM request ports carry only `addr` and `priority`, with no `write`, `data` or `strb`. No register goes with them (flops = RTL bits above); only the `allEmpty` reduction's comb logic is missing. This is the cost of a reader inside a streamer, which is what the model wants. A `ReaderEmitter`-style top-level reader would keep the ports. The xbar is its own top, so all its ports stay: `amo`, `priority` and `user` on both sides, which the TB ties to constants.
- **The xbar is all comb.** Its 256 flops are 1.4 % of its area, so its energy is 96 % combinational. DC took 4.6x the reader's time for 4.1x its area. Its VCD is 8x the reader's per cycle (61.5 MB for 1,025 cycles); `i64_b64` will need about 0.5 GB of disk during vsim.
